# T1590.004 — защита от разведки топологии сети на уровне коммутаторов

Материалы к статье «Реализация и анализ эффективности защиты от Gather Victim
Network Information: Network Topology (MITRE ATT&CK T1590.003) на уровне
коммутаторов» (Муфахаров А.М., Сафиуллин Я.А.). Стенд включает пять
устройств трёх производителей: Cisco, Eltex, MikroTik.

## Стенд

| Устройство | ПО | IP управления | Порт PC1 |
|---|---|---|---|
| Cisco WS-C2960-24-S | IOS 15.0(2)SE | — | Fa0/19 |
| Cisco WS-C2960-24TT-L | IOS 15.0(2)SE9 | — | Fa0/21 |
| Cisco WS-C3550-24 | IOS 12.2(25)SEE | — | Fa0/11 |
| Eltex MES1428 | ISS 10.2.5.2 | 10.19.103.30 | fastethernet 0/11 |
| MikroTik CRS326-24G-2S+ | RouterOS 7.22 | 10.19.103.27 | ether1 (10.10.10.0/24) |

PC1 (Alt Linux, атакующая машина) поочерёдно подключается к тестируемому порту
каждого устройства.

## Структура репозитория

```
configs/
  cisco/      — отключение CDP/LLDP + Port-Security (IOS), разд. 6.1 статьи
  eltex/      — проверка/демонстрация LLDP + контроль MAC (ISS), разд. 6.2 статьи
  mikrotik/   — discovery-settings + bridge filter (RouterOS), разд. 6.3 статьи
scripts/
  attacker/   — перехват CDP/LLDP и смена MAC-адреса, PC1 (Alt Linux)
```

## Методика (цикл для каждого устройства)

1. Зафиксировать конфигурацию протоколов разведки и контроля MAC «из коробки».
2. Атака — перехват служебного протокола (`scripts/attacker/capture_*.sh`).
3. Защита — применить конфигурацию из `configs/<vendor>/`.
4. Верификация — повторный перехват / проверка состояния (V=0, R=0).
5. Тест контроля MAC — смена MAC (`scripts/attacker/change_mac_and_test.sh`), проверка блокировки.

Метрики: V — число раскрытых полей, T — время до первого перехваченного пакета (с),
R — результат верификации (0/1).

**Ограничения метода** (см. раздел «Обсуждение» статьи): для Eltex MES1428
независимый перехват LLDP-кадров и тест с подменой MAC в рамках данного этапа
не проводился — выводы сделаны на основании конфигурационного состояния порта.
Для MikroTik повторный перехват после применения защиты также не выполнялся —
вывод R=0 основан на документации производителя.

## Как применить конфиг

Каждый файл в `configs/<vendor>/` — это не просто список команд, а подробная
инструкция: перед каждым блоком команд есть пояснение, что он делает, зачем,
какой результат ожидать при верификации, а также разделы «частые ошибки»
и «откат». Открывайте файл текстовым редактором и переносите команды
построчно, читая комментарии (строки, начинающиеся с `!` у Cisco/Eltex
и `#` у MikroTik).

**Cisco** (`configs/cisco/disable_cdp_lldp_and_port_security.txt`) —
`enable` → `configure terminal` → `interface FastEthernet0/X` (замените X на
реальный порт, см. `show ip interface brief`) → команды из файла →
`write memory` → верификация через `show cdp/lldp/port-security interface`.

**Eltex** (`configs/eltex/mes1428_lldp_and_port_security.txt`) — синтаксис
ISS, не Cisco IOS: команды `lldp run` / `show ports security` отклоняются
интерпретатором («Invalid input detected»). Использовать точный порт
`fastethernet 0/11` или заменить на актуальный (см. `show interfaces status`).
Обязательно `copy running-config startup-config` — иначе конфигурация
не сохранится после перезагрузки.

**MikroTik** (`configs/mikrotik/crs326_discovery_and_bridge_filter.rsc`) —
можно импортировать файл целиком:

```
/import file=crs326_discovery_and_bridge_filter.rsc
```

либо копировать команды по шагам через терминал/WinBox. Порядок правил
bridge filter важен: правило `accept` для легитимного MAC должно идти
**раньше** финального `drop`, иначе будет заблокирован и легитимный трафик
тоже — в файле это отдельно объяснено с примером проверки порядка правил
(`/interface bridge filter print`).
